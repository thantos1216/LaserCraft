# Milestone 0.10 validation

GRBL read-only connection diagnostics. Local build succeeds with zero warnings/errors. All 149 tests pass: 145 unit and 4 native integration.

The command/field behavior follows the upstream [GRBL command reference](https://github.com/gnea/grbl/blob/master/doc/markdown/commands.md) and [interface reference](https://github.com/gnea/grbl/blob/master/doc/markdown/interface.md). $I identifies the firmware, ? queries status and $$ retrieves settings. LaserCraft does not send assignments, reset/unlock, motion, spindle/laser or air commands through its monitor. The 2000 ms serial startup delay is an original configurable default; physical-board suitability is unverified. This protocol implementation does not require new REA binary analysis; prior REA reference evidence remains separate from protocol and hardware claims.

New automated coverage: optional telemetry with negative positions/additional axes and unknown raw fields; absent values remaining unknown; malformed/duplicate/nonfinite status rejection; settings source-value preservation; exact read-only simulator command sequence; empty, malformed, duplicate, error and alarm settings responses; 256-line incomplete response rejection; settings cancellation and queued status cancellation on disconnect; profile delay validation and legacy/default round-trip. Expected failures assert their exact exception types.

A real TCP loopback controller validates the actual transport: byte-fragmented CRLF identity, settings, intervening message and telemetry responses. It checks the precise $I, $$, ? sequence, settings completion before the next query, and preserved decimal text. This is real socket/framing coverage with a simulated controller, not physical firmware qualification.

Desktop simulator checks: disconnected read buttons disabled; Connect identifies the built-in simulator and shows Idle/MPos/feed/spindle; profile selection and duplicate Connect are disabled; Read firmware settings opens a read-only seven-setting report ($30=1000, $32=1), retains decimal source values and makes no changes; closing restores query controls; Disconnect restores profile selection and disables reads. A stale bottom connection label observed during this check was fixed by sharing the connection-state footer renderer. That final footer refresh fix has build coverage; a second interactive pass was not performed.

Unverified: physical serial opening/reset/delay/cancellation, actual USB driver faults, real GRBL/grblHAL/FluidNC variants, profile mismatch message through UI, and hardware job execution. No physical endpoint was selected or opened. Full configuration writes, free-form console input, homing/jogging/firing and streaming remain unavailable. Opening some serial boards can reset them; test only the intended user-selected endpoint.
