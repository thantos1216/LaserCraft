# Milestone 0.6 validation

Editable straight paths are the geometry foundation for later tracing and richer SVG support. Domain tests cover open/closed lengths, zero-width/height lines, relative and implicit SVG commands, compound holes, fill rejection for open paths, off-power transitions between contours, reflection/scaling, node renormalization and undo/redo, native/SVG round trips, shape conversion, stroke selection, malformed/unsupported SVG and fill-work limits. Prior raster/layer/device/export regression suites remain active.

Initial build: zero warnings/errors; 101 tests pass (99 unit, 2 native integration). Original fixtures are samples/paths-and-nodes.lcraft and samples/linear-paths.svg. No physical device was used.

REA inspect-managed-artifact inspected the independently built LaserCraft.Domain.dll, reporting static identity evidence in ignored tmp/path-domain-06.json. It did not execute or decompile code and does not prove behavioral parity. SVG path semantics were checked against https://www.w3.org/TR/SVG2/paths.html; this milestone deliberately implements M/L/H/V/Z, not curves/arcs. Move-only degenerate subpaths are rejected rather than silently discarded. Empty/trailing separators are tolerated by the subset tokenizer. CSS/transforms remain unsupported.

Limits: normalized polyline vertices, no Bézier handles, no node insert/delete/join/split, ellipse conversion is a 128-edge approximation, no image tracing yet. Open fill paths fail explicitly. Native format retains version 1 with appended ShapeKind.Path=3 and optional Path data; older builds reject that shape kind. Fill work is bounded by rows times edge count. Raster/controller execution limitations are unchanged.

Interactive validation: node dragging changed one vertex and one Undo restored the original clean document; Lines produced a closed three-vertex contour with C, and one Undo removed that object. The original sample plans 145 segments, 4493.1 mm cut and 185.6 s ideal time; its center remains uncut. Layer switching initially exposed an Avalonia selected-item enumeration crash caused by clearing items inside SelectionChanged. Row/dropdown selection now queues a coalesced dispatcher refresh after the selection transaction. Row switching was rechecked both in editing and preview, with no crash. Samples were not saved over. Native output/input tests remain simulator-only.
